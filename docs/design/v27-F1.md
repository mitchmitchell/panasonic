# kx-provision design v2.7 — F1 (A3)

Supersedes v2.6 F1. No FIDO2 or cryptographic mode signing.

## Mode and profile

- **Operational mode** (`Testing` | `Production`) lives in `{data_dir}/mode.json` (field `mode` only).
- **Monotonic counter** lives in `{data_dir}/mode.counter` (not inside `mode.json`).
- **Runtime profile** (`sim` | `test` | `prod`) lives in `{data_dir}/profile.json`.
- **Testing** mode is honored only when profile is `Test`; otherwise effective mode is **Production** (audit + alert, fail-closed).
- **Test** + **Testing**: apply does not require approval; other gates unchanged.
- **Sim** profile: no approval required (same as test writes); other gates unchanged.
- **Prod** profile: every apply requires a consumed approval.

## set_mode (root Unix socket only)

- Plain CLI/API: no signatures.
- Accepted **only while the daemon job queue is idle** (no queued or running jobs).
- Atomically: increment counter, write `mode.json`, update `profile.json` when profile changes, append audit.
- Counter rollback rejected on set.
- Missing/corrupt mode state: fail-closed to **Production** with audit + alert.

## submit_approval

- `plan_ref`: full 32-hex plan id **or** exactly **8** hex digits (prefix).
- Prefix must match **one** stored plan; **zero** → not found; **>1** → ambiguous prefix rejected.
- Other gates unchanged (Approve scope, diff_hash match, requester ≠ approver, TTL, rate limits).

## apply_plan response

- Result object contains only: `plan_id`, `diff_hash`, `status` (`completed` | `deferred`).

## kxprov sim-mark

- Records that simulator tests passed for the **current build hash** (compile-time `KXPROV_BUILD_HASH`).
- Marker path: `{data_dir}/sim-mark.json`.
- If the running build hash differs from the marker, the marker is **cleared** (invalid).
