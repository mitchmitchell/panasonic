# kx-provision design v2.7–v2.9 — F1 (A3)

Supersedes v2.6 F1. No FIDO2 or cryptographic mode signing.

## v2.8

- **N1:** Mode/profile switching is root CLI (`kxprov mode set`) only; declared HTTP/MCP route tables must not expose mode/profile (404/405).
- **N2:** Testing→Production switch compares live 0x24/0x25 wire to digest from last backup; mismatch blocks writes, audits, alerts Mitch (held 02:00–08:00 CT).
- **N3:** `sim-mark.json` is unsigned, mode **0600**, root-owned in production.
- **R3:** `live_writes_approved` defaults **false**; prod live writes stay gated.

## v2.9

- Pre-write **backup required on prod profile only**; not skippable via API flags.
- Rollback / unacked verify uses **plan stored base bytes** (kxtd1232 client); not backup bytes.
- **Apply** re-reads live base and re-hashes DiffHash at start; mismatch refuses.
- Header tail from backup applies only when assembling `.DBH` files.

## Mode and profile

- **Operational mode** (`Testing` | `Production`) lives in `{data_dir}/mode.json` (field `mode` only).
- **Monotonic counter** lives in `{data_dir}/mode.counter` (not inside `mode.json`).
- **Runtime profile** (`sim` | `test` | `prod`) lives in `{data_dir}/profile.json`.
- **Testing** mode is honored only when profile is `Test`; otherwise effective mode is **Production** (audit + alert, fail-closed).
- **Test** + **Testing**: apply does not require approval; other gates unchanged.
- **Sim** profile: no approval required (same as test writes); other gates unchanged.
- **Prod** profile: every apply requires a consumed approval.

## set_mode (root Unix socket only)

- Plain CLI/API: no signatures.
- Accepted **only while the daemon job queue is idle** (no queued or running jobs).
- Atomically: increment counter, write `mode.json`, update `profile.json` when profile changes, append audit.
- Counter rollback rejected on set.
- Missing/corrupt mode state: fail-closed to **Production** with audit + alert.

## submit_approval

- `plan_ref`: full 32-hex plan id **or** exactly **8** hex digits (prefix).
- Prefix must match **one** stored plan; **zero** → not found; **>1** → ambiguous prefix rejected.
- Other gates unchanged (Approve scope, diff_hash match, requester ≠ approver, TTL, rate limits).

## apply_plan response (v2.11)

- Either `{ "job_id": "..." }` when the apply job is queued, or
  `{ "plan_id", "diff_hash", "status": "approval_required" }` when G5 blocks (prod profile).

## submit_approval (v2.11)

- Params: `{ plan_id, diff_hash, profile }` — `plan_id` may be an 8-hex prefix; ambiguous prefix rejected; `diff_hash` must match exactly. No challenge field.

## Timing config (Tester #2, v2.11)

- Daemon `Config.timing` sets `link_baud` and `reply_guard_ms` (plus other `kxtd1232::Timing` fields).
- **Startup:** invalid timing fails closed — `reply_guard_ms` ≥ 20 ms, `link_baud` in `1..=115200`.
- Serial open uses configured `link_baud`; client uses the same struct for post-send cutoff math.

## Apply read-back

- Every plan chunk write on the sim transport (all profiles: Sim, Test, Prod) is followed by a read of the same span; mismatch aborts apply and can LOCK.

## kxprov sim-mark

- Records that simulator tests passed for the **current build hash** (compile-time `KXPROV_BUILD_HASH`).
- Marker path: `{data_dir}/sim-mark.json`.
- If the running build hash differs from the marker, the marker is **cleared** (invalid).
